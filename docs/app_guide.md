# App guide

The planner is a single static page in `app/`, with no server and no external scripts. Open `app/index.html` in a browser; it works straight from the file system. Every figure it shows comes from `app/params.js` (generated by `make app` from the project's committed outputs) or is computed in the browser from those parameters.

## What the page shows

- **The headline: the chance of reaching the goal under each assumption set, side by side.** There is no single headline number. The three plausible sets are the central assumptions (with their low–high range), the bias-corrected equity estimate, and historical equity with yield-based bonds. Historical global returns are shown as a reference. A sentence below the cards compares how far the answer moves between assumption sets with how far it moves between simulation engines and with sampling noise.
- **Monthly saving needed** for a chosen chance, under each set.
- **Charts**, for the set chosen with "Charts use":
  - The **fan chart** shows the middle 50% and 90% of simulated futures by year, the median, the middle of the worst 10%, and the same savings held in cash.
  - **Largest fall** shows the biggest peak-to-trough drop along the way, for each set.
  - Each chart has a "Show the numbers" table, and its values can be read by hovering or with the keyboard (arrow keys on the fan chart).
- **SRS (optional, simplified)** compares saving through SRS with investing the same money outside it.
  - The statutory retirement age is an input, defaulting to 64. It is fixed at your first SRS contribution, so it may be earlier for an existing account.
  - A warning appears when the goal date is earlier than that age.
  - The comparison doesn't value the loss of access before that age.

## The engine

The page runs a simplified engine: monthly returns drawn independently from a fat-tailed (Student-t) distribution fitted to SGD-era history, re-centred on each assumption set.

The project's main engine resamples actual history in blocks, which needs the monthly series. Their licences don't allow publishing those series, so the page ships only fitted parameters and computed results.

When the inputs match one of the four example investors, each card also shows the main engine's result and the measured gap. For other inputs, the page states the range of that gap across the examples. Rules: `docs/decisions.md` (Phase 3 pre-registration). Engine checks against the Python code: `tests/test_app_engine.py`; browser checks: `tests/test_app_page.py`.

## Updating

1. Run `make all`. It re-downloads changed sources, rebuilds the assumptions and the simulation, regenerates `app/params.js` and runs the tests. If a headline assumption or chance moves beyond its tolerance, the run stops and lists the change in `data/processed/drift_report.md`: review it, and delete the committed figures file named in the message only if the change is accepted.
2. Review the regenerated docs and `app/params.js`, then commit and push to `main`.
3. Deployment is automatic. A push that changes `app/` runs `.github/workflows/pages.yml`, which runs lint and the tests and then publishes `app/` to GitHub Pages. It can also be started by hand from the Actions tab.
